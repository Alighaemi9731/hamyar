## ۱) صفحه اول (Landing) — جهت‌گیری طراحی

### آیا Immersive باشد؟ — نه به شکل سنگینش. دلیل:
- مخاطب شما صاحب موبایل‌فروشی است، اغلب با گوشی اندرویدی میان‌رده و اینترنت ایران؛ صفحه‌های WebGL/سه‌بعدی/اسکرول‌جکینگ سنگین = LCP بالا، پرش کاربر، و افت سئو.
- هدف صفحه اول «کانورژن» است (ثبت‌نام آزمایشی ۱۴روزه)، نه جایزه طراحی. برای B2B ابزاری، وضوحِ ارزش > نمایش.
- **تصمیم: «Immersive-lite»** — یک لحظه‌ی امضایی تعاملی + بقیه صفحه آرام، سریع و دقیق. بودجه کارایی: بدون WebGL، JSِ لندینگ ≤ ۱۸۰KB gz، LCP < ۲.۵s روی 4G، احترام کامل به `prefers-reduced-motion`.

### بریف طراحی (بر پایه متد توکن‌محور)
- **سوژه و لحن:** دنیای واقعی پشتِ پیشخوان موبایل‌فروشی — IMEI، لیبل قیمت زرد، بارکد، قبض حرارتی، کشوی قطعات. لحن: «حرفه‌ای بازاری»، قابل‌اعتماد، بدون ادا.
- **پالت (۵ رنگ نام‌دار):**
  - `paper` ‏#F7F9FB — زمینه روشنِ سردِ تمیز (عمداً نه کرمِ گرم کلیشه‌ای)
  - `ink` ‏#0E1B2C — سرمه‌ای مرکبی برای متن/سطوح تیره
  - `brand` ‏#0FA3A8 — فیروزه‌ای کاشی ایرانی؛ رنگ CTA و لینک (پیوند بومی + حس فناوری)
  - `label` ‏#FFD84D — زردِ «لیبل قیمت»؛ فقط به‌عنوان امضای خرد (هایلایت قیمت/برچسب‌ها)، هرگز سطح بزرگ
  - سمانتیک محصول: success ‏#12A150 (وصول/پرداخت‌شده)، warning ‏#D97E00 (سررسید نزدیک)، danger ‏#D3363C (برگشتی/معوق)
- **تایپوگرافی:** تیتر = **استعداد (Estedad)** وزن‌های 700/800 با فاصله‌گذاری جمع‌وجور؛ متن = **وزیرمتن (Vazirmatn)**؛ اعداد جدولی `font-feature: tnum` برای همه ارقام مالی؛ لاتین fallback = Inter. مقیاس تایپ: 12/14/16/18/22/28/36/52.
- **چیدمان:** گرید ۱۲ستونه RTL با کانتینر ۱۱۵۲px؛ سکشن‌ها با ریتم عمودی ۹۶px؛ کارت‌ها گوشه ۱۲px و سایه‌ی یک‌لایه کم‌عمق (بدون سایه‌های رنگین‌کمانی).
- **عنصر امضایی (Signature):** هیروی «**قبض حرارتی زنده**» — سمت چپِ هیرو یک قبض ۸سانتی با لبه پرفراژ که خط‌به‌خط «پرینت» می‌شود و داستان واقعی محصول را روایت می‌کند: پذیرش تعمیر → پیامک «آماده تحویل» → تسویه → انتقال همتا. با اسکرول، وضعیت قبض جلو می‌رود (۳ فریم، بدون اسکرول‌جکینگ). این تنها لحظه‌ی پرخرج انیمیشنی صفحه است؛ بقیه فقط reveal ملایم.
- **کپی:** فارسی، فعل‌محور و مشخص («هر گوشی یک شناسنامه IMEI دارد»، نه «راهکار جامع هوشمند»). CTA اصلی: «۱۴ روز رایگان شروع کنید» — بدون کارت بانکی.

### ساختار سکشن‌های لندینگ (به ترتیب)
۱. هیرو: ادعای اصلی + قبض زنده + CTA دوتایی (شروع رایگان / دموی ۳دقیقه‌ای)
۲. نوار اعتماد: «مناسب فروش، تعمیرات، اقساط، چک» + شمارنده‌های واقعی بعد از لانچ
۳. ماژول‌ها به روایت مسئله→راه‌حل (۶ کارت: فروش سریالی، تعمیرات، اقساط/چک، پیامک، چندشعبه، گزارش سود)
۴. «شناسنامه IMEI» — اسکرین‌شات واقعی محصول با توضیح یک‌خطی (وجه تمایز اصلی)
۵. قیمت‌گذاری سه‌پلنه + افزودنی‌ها (همان جدول سند اصلی)
۶. سؤالات پرتکرار (همتا؟ مودیان؟ انتقال داده از نرم‌افزار قبلی؟ مالکیت داده؟)
۷. CTA پایانی + فوتر (نماد اعتماد/اینماد بعداً)
پیاده‌سازی: صفحه‌های عمومی داخل همان اپ لاراول (Blade + Tailwind، بدون React) تا سریع و SEO-پذیر باشد.

## ۲) دیزاین‌سیستم محصول — تا کل پنل یکدست بماند

### تصمیم: **shadcn/ui در حالت RTL + توکن‌های Tailwind v4 + گالری داخلی**
از ژانویه ۲۰۲۶ shadcn پشتیبانی درجه‌یک RTL دارد: با `"rtl": true` در `components.json`، خودِ CLI هنگام افزودن کامپوننت کلاس‌های فیزیکی را به منطقی تبدیل می‌کند (`ml-*→ms-*`، `text-left→text-start`، `left-*→start-*`)، آیکن‌های جهت‌دار را با `rtl:rotate-180` می‌چرخاند و انیمیشن‌ها را هم منطقی می‌کند (`slide-in-from-right→from-end`). دو نکته عملی: تبدیل خودکار برای استایل‌های جدید (`base-nova` و هم‌خانواده) است و برای کدهای قدیمی/قالبی باید یک‌بار `npx shadcn migrate rtl` اجرا شود؛ و برای المان‌های Portal (منو/پاپ‌اور) باید `dir` صریح پاس داده شود (باگ شناخته‌شده انیمیشن). این یعنی دیگر نیازی به پلاگین RTL جدا یا فورک کامپوننت‌ها نیست.

### ساختار سیستم (سه لایه)
1. **توکن‌ها** — تک‌منبع در `resources/css/app.css` با `@theme` تیل‌ویند v4: رنگ‌های بالا + سطوح (bg/fg/muted/border) + شعاع ۸/۱۲ + سایه ۲سطحی + z-index نام‌دار + توکن چگالی (`--density-compact` برای صفحات POS/جدول‌ها). دارک‌مود از روز اول با متغیر، نه کلاس‌های پراکنده.
2. **کامپوننت‌های پایه** — از shadcn نصب می‌شوند (Button, Input, Select, Dialog, Sheet, Tabs, Table, Toast/Sonner, Command, Badge, Tooltip, DropdownMenu, Popover, Skeleton) و فقط از طریق توکن‌ها رنگ می‌گیرند؛ دست‌کاری مستقیم رنگ در صفحات ممنوع.
3. **کامپوننت‌های دامنه (مال خود ماست):**
   `Money` (ریال، tnum، رقم فارسی/لاتین سوئیچ‌پذیر) · `JDatePicker`/`JDateRange` · `IMEIInput` (اسکن‌محور، اعتبارسنجی Luhn، autofocus) · `PartyPicker` و `UnitPicker` (جستجوی Command-باز) · `StatusBadge` (نگاشت وضعیت→رنگ سمانتیک، منبع واحد) · `StatCard` · `KanbanCard` تعمیرات · `EmptyState` با کپی فارسی اقدام‌محور · `PrintLayout.Thermal80` و `PrintLayout.A4/A5` (چاپ = بخشی از دیزاین‌سیستم، نه CSS پراکنده) · `DataTable` استاندارد (سرستون چسبان، جمع ستون، خروجی اکسل).

### قواعد سراسری (در اسکیل هم آمده تا Claude Code هر جلسه رعایت کند)
- فقط کلاس‌های **منطقی** (ms/me/ps/pe/start/end/text-start)؛ کلاس فیزیکی = باگ.
- `dir="rtl"` روی ریشه + پاس‌دادن `dir` به Portalها؛ ورودی‌های ذاتاً LTR (IMEI، موبایل، مبلغ لاتین) با `dir="ltr"` داخلی و ترازِ درست.
- ارقام: نمایش فارسی در متن، **لاتینِ جدولی** در جدول‌ها/فاکتورها (قابل‌تنظیم per-tenant).
- فرم‌ها: لیبل بالا، خطا زیر فیلد با متن قابل‌اقدام؛ Enter=ثبت در POS.
- دسترس‌پذیری کف کیفیت: فوکوس مرئی، کنتراست AA، اندازه لمسی ≥40px.
- **گالری UI** در مسیر `/design` (فقط محیط dev): همه کامپوننت‌ها + حالت‌ها + نمونه چاپ — به‌جای Storybook (سبک‌تر برای تیم تک‌نفره؛ Storybook بعداً اگر تیم بزرگ شد).
- هر PR که UI دارد باید از کامپوننت‌های گالری استفاده کند؛ کامپوننت جدید اول به گالری اضافه می‌شود بعد به صفحه.

## ۳) راه‌اندازی Claude Code — اسکیل‌ها، MCPها و پلاگین‌ها

### الف) قبل از پیست‌کردن مگاپرامپت (یک‌بار برای همیشه)
1. **Laravel Boost (مهم‌ترین نصب):** MCP رسمی تیم لاراول با ۱۵+ ابزار (خواندن اسکیمای DB، اجرای کوئری، لیست Routeها، Tinker، لاگ‌ها) + جستجوی معنایی در ۱۷هزار+ قطعه مستندات لاراول + «گایدلاین‌های AI» که به CLAUDE.md تزریق می‌شود.
   نصب بعد از ساخته‌شدن اسکلت لاراول در فاز ۰:
   `composer require laravel/boost --dev && php artisan boost:install`
   نکته‌ها: چون استک ما داخل Docker است اگر MCP خودکار وصل نشد، دستی رجیستر کنید:
   `claude mcp add -s local -t stdio laravel-boost docker compose exec -T app php artisan boost:mcp`
   و در ادغام گایدلاین‌ها با CLAUDE.md موجود، «قوانین طلایی» ما را بالای فایل نگه دارید (diff را ریویو کنید).
2. **Playwright MCP** (وریفای بصری/تعاملی): به Claude Code اجازه می‌دهد صفحه را باز کند، اسکرین‌شات بگیرد و جریان‌ها را کلیک کند — برای نقد طراحی و تست دستی خودکارِ فازها طلاست.
   `claude mcp add playwright -- npx -y @playwright/mcp@latest`
3. **اسکیل پروژه‌ای `hamyar-ui`** — فایل آماده در `claude-setup/.claude/skills/hamyar-ui/SKILL.md` این بسته است؛ کل پوشه `.claude/` را در ریشه ریپو کپی و کامیت کنید تا با تیم به اشتراک برود (اسکوپ پروژه = `.claude/skills/`، اسکوپ شخصی = `~/.claude/skills/`).
4. (اختیاری) **skill-creator** از مارکت رسمی انتروپیک برای ساخت اسکیل‌های بعدی خودتان:
   `/plugin marketplace add anthropics/claude-plugins-official` سپس `/plugin install skill-creator@claude-plugins-official`
5. (اختیاری) **Context7 MCP** برای مستندات به‌روز پکیج‌های غیرلاراولی (React/Inertia/shadcn)؛ ترکیب Boost + Context7 بیشترِ «حفره‌های دانشی» را می‌بندد.

### ب) قواعد بهداشت ابزار
- سقف عملی: **<۱۰ سرور MCP و <۳۰ ابزار فعال** در پروژه؛ هر ابزار اضافه = کانتکستِ کمتر برای کد. فقط Boost + Playwright (+Context7) کافی است.
- مارکت‌پلیس‌های شخص‌ثالث (مثل مجموعه‌های چندصدتایی اسکیل) قبل از نصب **بازبینی شوند** — اسکیل یعنی «دستورالعملی که مدل اجرا می‌کند»؛ از منبع ناشناس نصب نکنید. برای این پروژه به هیچ‌کدام نیاز نیست.
- اسکیل‌های سند‌ساز رسمی (docx/pdf/xlsx در ریپوی anthropics/skills) برای این پروژه لازم نیستند؛ اگر روزی خروجی ورد/اکسل از خود Claude Code خواستید نصبشان کنید.

### ج) چک‌لیست ماشین شما قبل از جلسه اول
Docker Desktop/Engine + Compose · Node LTS + npm (برای Vite و MCPهای npx) · Git · Claude Code نصب و لاگین‌شده · افزودن `*.app.localhost` به hosts (فاز ۰ خودش مستند می‌کند). PHP/Composer لوکال لازم نیست — همه‌چیز داخل کانتینر اجرا می‌شود؛ فقط دستور Boost بالا با `docker compose exec` تنظیم شده.

### د) چه چیزهایی به فایل‌های قبلی اضافه شد (این نسخه)

- مگاپرامپت: فاز ۰ حالا شامل نصب Boost و Playwright MCP، راه‌اندازی shadcn با `rtl:true` و توکن‌ها، ساخت `docs/design-system.md` از روی همین سند، و مسیر `/design` است؛ تسک لندینگ فاز ۱۱ هم به بریف بخش ۱ همین فایل ارجاع می‌دهد.
